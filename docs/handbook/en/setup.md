# Installation and build

## Required tools

| Tool | Version / note |
|---|---|
| Rust | stable (verified 1.99), via `rustup` |
| Rust targets for Android | `aarch64-linux-android`, `armv7-linux-androideabi`, `x86_64-linux-android` |
| `cargo-ndk` | 4.x (`cargo install cargo-ndk`) |
| Android Studio | includes a JDK (JBR) – no system Java needed |
| Android SDK | platform 37 (compileSdk), NDK 30 |
| `rustfmt`, `clippy` | `rustup component add rustfmt clippy` |

One-time setup:

```sh
rustup default stable
rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android
rustup component add rustfmt clippy
cargo install cargo-ndk
```

Gradle from the terminal needs the JDK bundled with Android Studio:

```sh
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
```

`apps/android/local.properties` (not in git) holds the SDK path:

```
sdk.dir=/Users/<user>/Library/Android/sdk
```


## Rust core

```sh
cargo build
cargo test
cargo clippy --all-targets
cargo fmt
```

The first build takes about 1.5 minutes (matrix-sdk is large); later builds are fast.

## Android

```sh
cd apps/android
./gradlew assembleDebug
```

Before every build Gradle runs `scripts/build-android.sh` (task `buildRustCore` in the
`:core-bindings` module). The script:

1. compiles `pocky-ffi` with `cargo-ndk` into
   `apps/android/core-bindings/src/main/jniLibs/<abi>/libpocky_ffi.so`,
2. generates the Kotlin bindings into
   `apps/android/core-bindings/src/main/kotlin/com/pokecio/app/core/pocky_ffi.kt`.

Both are generated and listed in `.gitignore`.

The script defaults can be changed with variables:

| Variable | Default | Meaning |
|---|---|---|
| `POCKY_ABIS` | `arm64-v8a` | Android ABI, e.g. `"arm64-v8a x86_64"` |
| `POCKY_PROFILE` | `android-dev` | Cargo profile (`release` for production) |
| `ANDROID_HOME` | `~/Library/Android/sdk` | SDK path |

The `android-dev` profile is an unoptimised build without debug info – fast to compile, but a
large `.so` (around 100 MB). The release build with LTO is much smaller.

### Installing on an emulator / phone

```sh
~/Library/Android/sdk/emulator/emulator -avd Pokecio_Test &
cd apps/android
./gradlew installDebug
```

### Android Studio

Open the `apps/android` folder. A build from Studio runs the same `buildRustCore`, so nothing has
to be started by hand.

## Map

Map tiles come from our own server `maps.pokecio.com`, which runs go-pmtiles (`pmtiles serve`)
behind nginx. The archive is `cz-sk.pmtiles` (Protomaps Basemap, Czech Republic and Slovakia,
zoom 0–15).

- TileJSON: `https://maps.pokecio.com/tiles/cz-sk.json`
- tiles: `https://maps.pokecio.com/tiles/cz-sk/{z}/{x}/{y}.mvt`

The map style, fonts and icons are bundled in the app (`apps/android/app/src/main/assets/map`,
about 0.9 MB). They are generated by `scripts/map-style`:

```sh
cd scripts/map-style
npm install
node build.mjs
```

Colours come from `design/tokens.json`. Fonts (Noto Sans, Latin and punctuation) and icons are
downloaded once from the Protomaps assets. At runtime the app talks only to `maps.pokecio.com`.

The map shows only the Czech Republic and Slovakia. The generator downloads the borders from
OpenStreetMap (relations 51684 and 14296 via polygons.openstreetmap.fr), merges them, simplifies
them to about 30 m and embeds them in the style as GeoJSON. Outside CZ and SK the map is fully
black. Germany, Austria and Poland (`UPCOMING`) are dark silhouettes with an outline and a
"Coming soon" label in the middle. A purple line highlights the CZ and SK border. `PockyMap` keeps
the camera over the archive area and does not allow zooming out below 5.5.

When the archive is replaced (for example with all of Europe), change `TILES` and `COUNTRIES` in
`build.mjs` (or drop the mask) and `CoveredArea` and `HomeCenter` in `ui/map/PockyMap.kt`.

## Disk space

The `target/` folder grows quickly (Mac + Android builds). The `dev` profile therefore generates
debug info only for our crates, not for dependencies. When space runs out:

```sh
cargo clean
cd apps/android && ./gradlew clean
```

## Release APK

```sh
scripts/release-android.sh
```

- The core in the `release` profile (LTO, 1 codegen unit, no symbols), `arm64-v8a` only (other ABIs
  via `POCKY_ABIS`).
- Android code through R8 (`isMinifyEnabled`, `isShrinkResources`); rules for JNA / UniFFI /
  rustls are in `core-bindings/consumer-rules.pro`.
- The first build takes about 18 minutes (LTO over matrix-sdk); later ones are faster.
- Output: `apps/android/app/build/outputs/apk/release/app-release.apk`, about 70 MB (the debug APK
  is ~200 MB). Most of it is `libpocky_ffi.so`, stored uncompressed for a faster start (decision:
  keep it that way – compression would save space in the download, but the first start would be
  slower and the app would take more space on the phone).

### Signing

The key never goes into git or code – only through environment variables:

```sh
keytool -genkeypair -v -keystore ~/pockyapp-release.jks -alias pockyapp \
  -keyalg RSA -keysize 4096 -validity 10000

export POCKY_KEYSTORE=~/pockyapp-release.jks
read -s "POCKY_KEYSTORE_PASSWORD?Keystore password: " && export POCKY_KEYSTORE_PASSWORD && echo
export POCKY_KEY_ALIAS=pockyapp
read -s "POCKY_KEY_PASSWORD?Key password: " && export POCKY_KEY_PASSWORD && echo
scripts/release-android.sh
```

Without `POCKY_KEYSTORE` the APK is signed with a debug key – for testing only, do not distribute.
The `.jks` file is in `.gitignore`; back it up safely, without it no update can be released.
