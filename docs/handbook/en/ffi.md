# Platform API – `pocky-ffi`

Path: `core/pocky-ffi/src/`. Kotlin package: `com.pokecio.app.core` (set in
`core/pocky-ffi/uniffi.toml`).

The bindings are generated by `scripts/gen-bindings.sh`; never edit them by hand.

## Functions

```kotlin
coreVersion(): String

suspend createClient(dataDir: String, passphrase: String?): PockyClient
suspend restoreClient(session: String, dataDir: String, passphrase: String?): PockyClient
```

- `createClient` is for a **new sign-in**: it deletes `dataDir` and discovers the `pokecio.com`
  server through `.well-known`.
- `restoreClient` uses a stored session (JSON) and the existing store.

data folder**. It deletes the data even when the network is down; it then returns `Network`, but
locally the user is signed out. `deleteAccount` deactivates the account on the server with data
erasure and then deletes the data folder the same way.

## Verification

```kotlin

suspend confirm()       // the emoji match

```

```kotlin
sealed class VerificationStep: Requested, Incoming, Ready, Starting,
    Emojis(emojis: List<VerificationEmoji>), Confirmed, Done, Cancelled(byUs, reason)

data class VerificationEmoji(index: UByte, symbol: String, description: String)
```

`index` is the emoji's position in the Matrix specification (0–63); Android uses it to pick the
Czech name from `res/values/emoji.xml`.


## Listeners

```kotlin
interface RoomListListener   { fun onUpdate(rooms: List<Room>) }
interface SyncStatusListener { fun onUpdate(status: SyncStatus) }
interface TimelineListener   { fun onChanges(changes: List<TimelineChange>) }
interface EncryptionListener { fun onUpdate(info: EncryptionInfo) }
interface VerificationListener { fun onStep(step: VerificationStep) }
interface VerificationRequestListener { fun onRequest(verification: Verification) }
```

They are called from core threads, not from the main thread. In Kotlin, only write into a
`StateFlow` (it is thread-safe); never touch the UI directly.

## Android: TLS initialisation

Rust networking verifies certificates with the Android system store (`rustls-platform-verifier`).
It needs the JVM, so **before the first network call** this must run:

```kotlin
TlsVerifier.init(context)   // com.pokecio.app.tls, called by PockyApp.onCreate
```

The JNI function is in `core/pocky-ffi/src/android.rs`. Without the initialisation every network
request panics with "Expect rustls-platform-verifier to be initialized".

## Adding a new function to the API

1. Write the logic in `pocky-core` (+ tests).
2. Add a thin wrapper in `pocky-ffi`: type conversion, call through `run()`.
3. `./scripts/gen-bindings.sh` (or simply a Gradle build).
4. Use it in Kotlin.

Never name a method `close` – it clashes with the generated `close()` in Kotlin.
