# Architecture

## Layers

```
┌──────────────────────────────────────────────┐
│ Android UI (Compose)                         │  screens, display only
├──────────────────────────────────────────────┤
│ Android state (ViewModel, controllers)       │  StateFlow, lifecycle
├──────────────────────────────────────────────┤
│ Kotlin bindings (generated by UniFFI)        │  com.pokecio.app.core
├──────────────────────────────────────────────┤
│ pocky-ffi (Rust)                             │  FFI types, tokio runtime, tasks
├──────────────────────────────────────────────┤
│ pocky-core (Rust)                            │  all client logic
├──────────────────────────────────────────────┤
│ matrix-sdk, matrix-sdk-ui                    │  protocol, encryption, storage
└──────────────────────────────────────────────┘
```

The ground rule: no logic in the UI. Anything two platforms would need belongs in `pocky-core`.

## Why two Rust crates

- **`pocky-core`** is plain Rust without UniFFI. It can be tested with ordinary tests and will serve
  every platform unchanged.
- **`pocky-ffi`** only converts core types into UniFFI types, owns the tokio runtime and runs
  long-lived tasks (sync, list observers). No logic of its own.

The web app uses the same core through WebAssembly; it is developed separately.

## Data flow

### Sign-in

```
LoginScreen → MainViewModel.login()
  → createClient(dataDir, passphrase)        new empty store
  → client.login(user, password, device)     returns the session as JSON
  → SessionStore.saveSession(json)           encrypted (Keystore)
  → RoomListController + MediaLoader         LoggedIn state
```

### App start

```
MainViewModel.restore()
  → SessionStore.loadSession()
  → restoreClient(session, dataDir, passphrase)   works offline too
  → LoggedIn, sync starts when the app is in the foreground
```

### Sync and the room list

- `SyncService` from matrix-sdk-ui runs over **sliding sync** (Synapse supports it natively,
  `org.matrix.simplified_msc3575`).
- It runs in offline mode – when the network drops it switches to `Offline` and recovers on its own.
- The core sends the room list as **the whole sorted list** on every change. For tens to hundreds of
  rooms that is enough, and it keeps the Kotlin side simple.
- Sync runs only in the foreground (`LifecycleStartEffect` in `MainActivity`).

### Timeline

- `Timeline` from matrix-sdk-ui handles edits, redactions, reactions, replies, read receipts,
  decryption and the send queue.
- Only **diffs** go to Kotlin (`TimelineChange`: insert, set, remove, reset…), because the timeline
  changes often and can hold hundreds of items.
- Kotlin (`RoomController`) applies the diffs to a list and `buildRows` turns it into display rows.
- Read receipt tracking has to be switched on explicitly
  (`track_read_marker_and_receipts`); matrix-sdk-ui keeps it off by default.

### Media

- A media source is an opaque string: `mxc://…` or the JSON of an encrypted file.
- `loadMedia(source, w, h)` asks the server for a thumbnail for unencrypted media; encrypted media
  is downloaded and decrypted. The result is cached in the encrypted store.
- Android keeps decoded images in an in-memory LRU cache.

## Threads and runtime

- `pocky-ffi` has its own multi-threaded tokio runtime (`pocky-core` threads).
- Every call from Kotlin runs on this runtime (`run()` in `lib.rs`).
- Core objects (`PockyClient`, `RoomTimeline`) are dropped inside the runtime context. Without that,
  the SQLite pool from matrix-sdk panicked when dropped on the Android main thread and the app
  crashed.
- Long-lived tasks (list, timeline and state observers) return a `TaskHandle`. A task ends after
  `cancel()` or when Kotlin discards the object.

## Server

| What | Value |
|---|---|
| Server name | `pokecio.com` |
| Homeserver (from `.well-known`) | `https://matrix.pokecio.com` |
| Sign-in | `m.login.password` only |
| Registration | disabled (403) |
| Sliding sync | yes |
| OIDC / QR sign-in | no |

On a new sign-in the client discovers the homeserver through `.well-known`. When restoring a
session it uses the stored homeserver URL, so the app starts without network too.

## Key decisions

| Decision | Reason |
|---|---|
| The session is just a JSON string for Kotlin | The token never appears as a field in Kotlin and cannot end up in a log by accident |
| Own tokio runtime in the FFI | Objects can be dropped safely from any thread |
| Whole room list, timeline as diffs | Simplicity where it is enough, performance where it is needed |
| State changes as a structure, not a sentence | Each platform builds the text in its own language |
| Technical state events hidden | Permissions, join rules, ACLs and so on only clutter the timeline |
| Automatic history back-pagination on | Otherwise rooms with a reaction or membership change on top have no last-message preview |
| No Compose Navigation | Few screens; state in the ViewModel survives rotation |
| Image loading without Coil | Caching and decryption are handled by the core; Kotlin only decodes |
