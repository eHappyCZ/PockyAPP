# Self-hosting the web app

The PockyAPP web app is a static site: HTML, JavaScript and the Rust core compiled to WebAssembly.
It needs no server-side code of its own and works with any Matrix homeserver that allows signing
in with a password. This guide shows how to build and run it for your own server.

## What you need

- **A Matrix homeserver** reachable over HTTPS, with:
  - password sign-in (`m.login.password`); servers that only offer sign-in through the browser
    (OIDC / Matrix Authentication Service) are not supported yet,
  - native (simplified) sliding sync – a recent Synapse has it built in,
  - `/.well-known/matrix/client` on the server name if the homeserver runs on another host
    (e.g. `example.org` → `https://matrix.example.org`).
- **A web server** with HTTPS (the examples use nginx).
- **Build tools:** Rust stable with the `wasm32-unknown-unknown` target, `wasm-bindgen-cli` in the
  version from `Cargo.lock`, Node.js and npm. `wasm-opt` from binaryen is optional and makes the
  core smaller.

```sh
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version 0.2.129 --locked
```

## Configuration

Everything deployment-specific lives in `apps/web/pocky.config.json`:

```json
{
  "defaultServer": "example.org",
  "allowOtherServers": false,
  "connect": ["https://example.org", "https://matrix.example.org"],
  "mapTiles": ""
}
```

| Key | Meaning |
|---|---|
| `defaultServer` | The server name shown on the sign-in screen (the part after `:` in user IDs) or a full homeserver URL. |
| `allowOtherServers` | `false`: people can sign in only to `defaultServer`. `true`: the sign-in screen gets a "Change" button and anyone can use their own server. |
| `connect` | The origins the browser may talk to when `allowOtherServers` is `false`: the server name (for `.well-known`) and the homeserver itself. |
| `mapTiles` | A TileJSON URL of a vector tile source in the Protomaps basemap schema. Leave it empty to hide maps and sending locations. |

The Content Security Policy is generated from this file (`apps/web/security.js`):

- with `allowOtherServers: false` the browser may connect only to the origins in `connect` and the
  map tiles,
- with `allowOtherServers: true` it may connect to any `https:` origin, because the homeserver is
  not known in advance. Scripts, frames, forms and plugins stay blocked either way.

Please do not point `mapTiles` at `maps.pokecio.com`; that server only serves the Pokecio
deployment. A small self-hosted alternative is [go-pmtiles](https://github.com/protomaps/go-pmtiles)
serving an extract of the [Protomaps basemap](https://docs.protomaps.com/basemaps/downloads). The
bundled map style is generated by `scripts/map-style` (see [setup.md](setup.md#map)); its view is
limited to the Czech Republic and Slovakia, so adjust `COUNTRIES` there for another region.

## Build

```sh
scripts/build-web.sh
```

The script builds the core for the web (about 8 minutes the first time), copies the map style,
type-checks and builds the app, writes `apps/web/deploy/headers.conf` with the security headers and
adds `.gz` copies for `gzip_static`. The result is `apps/web/dist/`.

## Deployment with nginx

1. Copy the content of `apps/web/dist/` to the web root, e.g. `/var/www/pockyapp`.
2. Copy `apps/web/deploy/headers.conf` to `/etc/nginx/snippets/pockyapp-headers.conf`. Upload it
   again after every change of `pocky.config.json` or `security.js`.
3. Use `apps/web/deploy/nginx.example.conf` inside your `server { … }` block with HTTPS and adjust
   the paths.
4. `nginx -t` and reload nginx.

The example serves `index.html` with `no-cache`, fingerprinted files in `/assets/` with a one-year
cache and the map style in `/map/` for a day. Do not enable a reverse proxy in front of the static
files and keep the security headers inside each `location` block; nginx does not inherit
`add_header` into blocks that define their own.

## Homeserver checklist

- `https://<server name>/.well-known/matrix/client` returns the homeserver URL and allows
  cross-origin requests (`Access-Control-Allow-Origin: *`).
- The homeserver answers `/_matrix/client/versions` from the browser (Synapse sends the CORS
  headers itself).
- Password sign-in is enabled. Registration happens outside the app for now.

## What the web app stores

Everything stays in the browser: the session and the encryption keys are in IndexedDB, encrypted
with a random passphrase that is itself kept in a WebCrypto key which cannot be exported. Signing
out deletes all of it. The app sends no analytics and loads no third-party scripts.

## The Android app and other servers

The Android app can sign in to another server too (Server · Change on the sign-in screen). Push
notifications then still go through the Pokecio push gateway (it receives only the event and room
IDs, never message content) and maps come from `maps.pokecio.com`.
